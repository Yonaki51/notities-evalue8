# Plan: conditional email snippets

## What exists today

The Phase Zero Installation Details section in `resources/views/livewire/planboard/edit/order-information.blade.php` already has these project selections:

| Selection | Stored project field |
| --- | --- |
| Installation by evalue8 | `installation_by_evalue8` |
| Power connection points identified | `power_connection_points_identified` |
| Network connection points known | `network_connection_points_known` |
| Power and network connections known | `power_and_network_connections_known` |
| Network details known | `network_details_known` |

`app/Livewire/Planboard/Edit/OrderInformation.php` saves each selection as true, false, or null (not selected). The four detail selections appear only when Installation by evalue8 is set to yes. These fields already have migrations and boolean casts in `app/Models/Project.php`. Do not add `contact_point` or `internet_point` columns: the project does not have fields with those names. Each of the four detail selections matches a snippet only when its saved answer is **no** (`false`). An answer of yes or no selection (`null`) does not match. Installation by evalue8 does not have its own snippet.

The email-template edit screen has a hard-coded Snippets tab entry called “Installation details feedback.” `ModalEmailTemplateComponent` currently renders it from `resources/views/components/emailtemplates/snippets.blade.php`. This is test data: replace that entry and its rendering with the new database-backed variable. The old view mistakenly uses either `power_and_network_connections_known` or `network_details_known` to show “Netwerkgegevens onbekend.” That paragraph should have checked only `power_and_network_connections_known`. Do not carry the combined condition into the new implementation; `network_details_known` has its own separate snippet.

Each of the four detail fields can have one configured snippet. Use their field names as trigger keys and display them in dropdown order: `power_connection_points_identified`, `network_connection_points_known`, `power_and_network_connections_known`, `network_details_known`.

## Expected behavior

Administrators can list snippets on a configurator page. Only super admins can create, edit, and delete snippets. The create and edit forms offer the four supported detail fields in a selector. Require confirmation before deletion. Deleting a snippet must not silently block email sending: warn in the preview if a project needs a snippet that no longer exists.

An email-template author can insert one clickable variable, `{{$mappedVariables["projectSnippets"]}}`, into the email body. When a user opens the email preview, the app checks `installation_by_evalue8` first. Unless its value is yes, it inserts nothing. If it is yes, each of the four detail fields with a no answer inserts its configured snippet, in dropdown order. Yes and unanswered detail fields insert nothing. The variable produces no content if no rules match. A template without the variable stays unchanged. Show a non-blocking preview warning for a matching detail field without a configured snippet, but allow sending. Sending uses the content currently shown in the editor, including manual changes; opening a new preview loads the latest snippet content.
